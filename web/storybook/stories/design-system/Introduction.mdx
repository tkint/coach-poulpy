# Coach Poulpy design system

The app is calm and rounded, like the plush: one blue accent for actions, white or near-white surfaces, and only Poulpy and the Home header tint with his mood. Values live in [`design/tokens.json`](https://github.com/tkint/coach-poulpy/blob/main/design/tokens.json) and are generated into each platform (see [`design/README.md`](https://github.com/tkint/coach-poulpy/blob/main/design/README.md)); these rules say how to use them. The live swatches are on the [Tokens](?path=/docs/design-system-tokens--docs) page of the component workshop.

The landing site, the web app and these pages draw with one package, [`web/ui`](https://github.com/tkint/coach-poulpy/tree/main/web/ui): DaisyUI with the Poulpy theme and a few Vue components on top ([ADR 0023](https://tkint.github.io/coach-poulpy/docs/adr/0023-the-websites-share-one-vue-and-daisyui-design-system)). This workshop is its home ([ADR 0028](https://tkint.github.io/coach-poulpy/docs/adr/0028-storybook-is-the-component-workshop-of-the-design-system), [ADR 0029](https://tkint.github.io/coach-poulpy/docs/adr/0029-mockups-are-stories-in-the-component-workshop)).

- **Rules**: how to use [colour](?path=/docs/design-system-rules-colour--docs), [type](?path=/docs/design-system-rules-type--docs), [space, radius and motion](?path=/docs/design-system-rules-space-radius-and-motion--docs), [icons](?path=/docs/design-system-rules-icons--docs), [accessibility](?path=/docs/design-system-rules-accessibility--docs), the [components](?path=/docs/design-system-rules-components--docs), the [screens](?path=/docs/design-system-rules-screens--docs) and the [websites](?path=/docs/design-system-rules-websites--docs).
- [Tokens](?path=/docs/design-system-tokens--docs): every value, read from `design/tokens.json`.
- **Core**: what is the same on every platform: Poulpy and the body map. They are drawn here with the web components.
- **Web > Components**: each Vue component in every state, with its classes. Each state is a story and runs as a test in CI, with an accessibility check. Use the toolbar to switch between light and dark.
- **Mobile > Components**: the raw pieces of the Android and iOS screens (buttons, chips, fields, rows), one page each, with a story per variation and controls to try them.
- **Mobile > Patterns**: pieces composed from those, such as the nav bar, sheets and charts.
- **Mobile > Screens**: every agreed phone screen, grouped by bottom-bar tab (Home, Library, You) and then by view, built from the components and patterns, and the drafts ([ADR 0029](https://tkint.github.io/coach-poulpy/docs/adr/0029-mockups-are-stories-in-the-component-workshop)).

## Classes

Every DaisyUI class carries the `cp-` prefix (`cp-btn`, not `btn`); the few classes of our own (`cp-chip`, `cp-stepper`, `cp-type-*`...) never reuse a DaisyUI name. Tailwind's own utilities (`w-full`, `bg-secondary`) have no prefix. A component's docs page lists the classes it renders.

Type has plain classes and no component: `cp-type-display`, `cp-type-title`, `cp-type-headline`, `cp-type-label`.
