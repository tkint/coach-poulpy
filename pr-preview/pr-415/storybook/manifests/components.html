# Coach Poulpy design system

The landing site, the web app and these pages draw with one package, [`web/ui`](https://github.com/tkint/coach-poulpy/tree/main/web/ui): DaisyUI with the Poulpy theme and a few Vue components on top ([ADR 0023](https://tkint.github.io/coach-poulpy/docs/adr/0023-the-websites-share-one-vue-and-daisyui-design-system)). This workshop is its home ([ADR 0028](https://tkint.github.io/coach-poulpy/docs/adr/0028-storybook-is-the-component-workshop-of-the-design-system), [ADR 0029](https://tkint.github.io/coach-poulpy/docs/adr/0029-mockups-are-stories-in-the-component-workshop)).

- [Rules](?path=/docs/design-system-rules--docs): how to use colour, type, space, components and Poulpy.
- [Tokens](?path=/docs/design-system-tokens--docs): every value, read from `design/tokens.json`.
- **Components** (in the sidebar): each Vue component in every state, with its classes. Each state is a story and runs as a test in CI, with an accessibility check. Use the toolbar to switch between light and dark.
- The Android and iOS components and the mockups are on the [docs site](https://tkint.github.io/coach-poulpy/mobile-components) until they move here ([ADR 0029](https://tkint.github.io/coach-poulpy/docs/adr/0029-mockups-are-stories-in-the-component-workshop)).

## Classes

Every DaisyUI class carries the `cp-` prefix (`cp-btn`, not `btn`); the few classes of our own (`cp-chip`, `cp-stepper`, `cp-type-*`...) never reuse a DaisyUI name. Tailwind's own utilities (`w-full`, `bg-secondary`) have no prefix. A component's docs page lists the classes it renders.

Type has plain classes and no component: `cp-type-display`, `cp-type-title`, `cp-type-headline`, `cp-type-label`.

# Tokens

Every value below is read from [`design/tokens.json`](https://github.com/tkint/coach-poulpy/blob/main/design/tokens.json) when the workshop is built, the same file that generates the Android, iOS and web themes ([ADR 0012](https://tkint.github.io/coach-poulpy/docs/adr/0012-design-tokens-generated-from-one-file)). How to use them is on the [Rules](?path=/docs/design-system-rules--docs) page.

export const roles = Object.keys(tokens.theme.light).filter((name) => !name.startsWith('on'))
export const onRole = (role) => {
  const name = 'on' + role[0].toUpperCase() + role.slice(1)
  return name in tokens.theme.light ? name : null
}
export const family = (font) => (font === 'display' ? "'Baloo 2', sans-serif" : 'Nunito, sans-serif')

## Colour roles

Each role with its text colour, in light and dark.
