Roadmap ​

What ships and in which order. Version 1.0 is the app, the accounts and sync, the website and the admin as they are drawn in the agreed mockups. Everything built or mocked up today is in it. What is not mocked up yet, and everything after 1.0, is listed below with what blocks it.

Release numbers after the current one can change as the work is planned. The current version is the latest tag on the Releases page.

How it is planned ​

  • A phase is a stage of the product. Phase 1 is Version 1; phase 2 is everything after 1.0.
  • A release is a set of features that make sense together, cut when it is ready, not on a date (Releasing). It has a version and a theme, such as 0.12 · Find and reuse.
  • A milestone on GitHub is one release, named after it and naming its phase. Every issue has exactly one milestone, Later when it is not planned.
  • A version is 0.x until Version 1 is complete, then 1.0. Releases after 1.0 get their numbers when they are planned.

A GitHub release with the Android APK, plus the server deployed on Infomaniak, is production. Publishing in the app stores comes after 1.0.

Where we are ​

The latest release is v0.10.0. The next one, 0.11, is complete on main and waits to be tagged.

What already ships ​

  • The app on both phones. A catalog of exercises downloaded from the server, the workout builder (circuit or sets, in parts), the library with search and filters, a workout page with its body map, the guided player, Live recording from a treadmill over Bluetooth (FTMS), the session recap, share cards, .FIT export, and workout files to send to another phone.
  • Accounts and sync. Sign up with email and password, confirm by email, sign in and out, reset a password, delete an account, and sync workouts, sessions, planned workouts, the body log and settings between phones (Accounts, Sync).
  • The server. The API, Postgres and a Docker deploy to one server (Deploying the server).
  • The website. Sign in, confirm email, reset a password, the workouts and the profile (The web app).
  • The admin. Audit log, accounts (find, disable, confirm by hand, delete), mail settings, server status, and the exercise catalog with drafts, publishing, retiring and offering by revision (The admin area).

Not yet placed ​

These are in the Later milestone until they have a release.

  • Tailored workouts in the catalog. Curated workouts and plans, each at one of three levels, browsed in the catalog and shown in the list beside a person's own, copied when edited (ADR 0034). The maintainer has decided the model; the issues, the admin editor and the mockups come next, and it is not placed in a release yet. Level suggestions, effort ratings after a session and curated plans stay out of the first version.
  • Rethinking the workout player and the live recorder as one idea (#225). A design discussion first; ADR 0018 stays in force until then.
  • Poulpy's animations (#537) and his looks (drawn as drafts in the brand pages).

Wanted but not planned: #30 control the treadmill, #31 heart rate straps, #32 user-created exercises, #33 progression rules, #75 guided building of a long run, #124 Poulpy's coaching style, #228 APIs and an MCP server, #481 direct Garmin telemetry, and the You blocks without a mockup (#527 to #530).

Dropped: swapping an exercise during a session (#38).

Not tied to a release ​

Documentation and tooling work (#227 readability, #353 mockup interactions, #398 diagrams) and #229, which defines how releases are planned, go in the milestone of the next release to ship.
