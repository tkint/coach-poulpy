Design system ​

The app is calm and rounded, like the plush: one blue accent for actions, white or near-white surfaces, and only Poulpy and the Home header tint with his mood. Values live in design/tokens.json and are generated into each platform (see design/README.md); this page says how to use them. The live swatches are on the site's Tokens page.

Colour roles ​

Use roles, never raw palette steps, in screens. Each role has a light and a dark value.

RoleUse it for
primary / onPrimaryThe main action on a screen (Start session, Save), selected chips, links, progress
primaryContainer / onPrimaryContainerTonal buttons, selected rows, Poulpy's speech on the blue side
grumpy / onGrumpyThe one action offered while Poulpy is on the ember side (Catch up, Flip him back)
grumpyContainer / onGrumpyContainerThe Home header and cards while Poulpy is on the ember side
background, surface, surfaceVariantScreen, cards and sheets, inset fields and steppers
onSurfaceVariant, outlineSecondary text and captions; card borders and dividers
successA confirmed save or a finished phase, with a check icon
error / onErrorErrors only: crimson, always with an icon and words
heat1, heat2, heat3How much a workout works each muscle on the body map, from a little to most. Orange, on the body map only: never for Poulpy's moods
painA worked area that hurts, outlined on the body map. Purple, so it reads apart from the heat and is never mistaken for an error

Rules:

  • poulpy.blue, poulpy.ember and poulpy.ink are Poulpy's fabric and never change between light and dark.
  • The plush blue and ember are too light for white text: buttons use primary and grumpy.
  • Ember means "a session slipped", never "something broke". An error is crimson, so a cross Poulpy is never read as a failure.
  • Colours that must be told apart also differ in lightness, not hue alone.

Mood shades ​

Six shades, from mood.*, only on Poulpy himself, the Home header tint and mood-coloured charts:

SideShades, calmest to strongest
Blue (on track)recovering, happy, proud
Ember (a session slipped)annoyed, grumpy, fuming

Which shade shows when is in Brand.

Type ​

Baloo 2 for display and titles, Nunito for everything else. Platforms map each role to a system text style so Dynamic Type and font scaling keep working (.font(.poulpy(.headline)) on iOS, MaterialTheme.typography on Android).

RoleFontSize / lineUse
displayBaloo 2 80040 / 44Poulpy's line on Home, end-of-session headline
titleBaloo 2 70028 / 32Screen titles, workout name on its page
headlineBaloo 2 70021 / 25Section heads, the current exercise in the player
bodyNunito 50016 / 24Everything you read
labelNunito 800, tracked 0.08 em, upper case12.5 / 16Eyebrows, tab labels, "Next up"
timerNunito 800, tabular figures64 / 64Timers and rep counts, which must not jitter

Words never break. Translations run longer than English (« Bibliothèque », « Échauffement »), so text is laid out for any length:

  • Text in a space of fixed width (tab labels, chips, stat tiles, stepper values) stays on one line and shrinks to fit, never below 9 sp / pt; past that it ends in an ellipsis. FitText on Android, .lineLimit(1).minimumScaleFactor(…) on iOS, whose tab bar already does it.
  • Buttons wrap their label between words rather than shrink it.
  • Every other text wraps between words only, never inside one, and never hyphenates.

Space, radius, motion ​

  • Spacing steps: 4, 8, 12, 16, 24, 32, 48 (xs to xxxl). Pick a step; never a value between them.
  • Radius: 8 for chips and small fields, 10 for cards and rows, 14 for sheets, pill for buttons. Small cards stay close to square so their text reads first.
  • Controls stay compact: a standard button is 44 high, a large one 52, an icon button 40 (its touch area stays 44), a small button 34. The side gutter of a screen is 16, and rows are 56 high with a 32 to 40 avatar. In the apps these come from one place, PoulpySize (generated from design/tokens.json, next to PoulpySpace and PoulpyRadius); a screen never writes a literal height, gutter or corner radius.
  • Motion: the flip (700 ms with overshoot) is the one signature move, used only when Poulpy changes side. Mood shades fade in 300 ms. Everything else is 150 to 250 ms and plain. With reduced motion on, the loader slows to one turn in 10 s.

Screens ​

Mockups are plain HTML in design/mockups/ (ADR 0016). They are split by stage (drafts/ and agreed/) and platform (phone/, tablet/, web/).

  • Build from an agreed mockup. If a screen has none, agree one through a PR before building it.
  • The Mockups gallery shows each app view and its available states in light and dark themes.
  • CI checks mockup links, local assets, design tokens and required metadata with node design/check-mockups.mjs.

The mockup is the design reference; this page defines the shared rules and components used to build it.

Websites ​

The landing site, the web app, the web mockups and the docs site share one package, web/ui: DaisyUI with the Poulpy theme and a few Vue components (ADR 0023). The live samples and the class of each component are on the Web components page.

  • Use the shared components (CpButton, CpChip...) in Vue, and their classes in a web mockup; never restyle a DaisyUI class in an app. A missing shape goes in web/ui, with its sample and its section on the Web components page in the same PR.
  • Every DaisyUI class carries the cp- prefix (cp-btn cp-btn-primary). Our own classes (cp-chip, cp-stepper, cp-type-label...) never reuse a DaisyUI name, so the two cannot clash.
  • The roles above keep their meaning: cp-btn-primary is primary, cp-btn-secondary is the tonal primaryContainer, cp-btn-accent is grumpy and only for the catch-up action. Never use DaisyUI's warning classes: ember is not a warning, and a problem is an error.
  • A web mockup that fills the browser window, such as one with a CpDrawer sidebar, adds <meta name="mockup:viewport" content="800">: the docs site then shows it in a window of that height and the page scrolls inside it, since a frame sized to a page as tall as the frame would grow forever. design/mockups/shared/mockup-drawer.js opens such a drawer on a large screen. Web mockups link web/ui/src/tokens.css then web/ui/poulpy-ui.css. The generated CSS is ignored by Git: the web and docs-site builds generate it from web/ui/src/, and the docs build copies it alongside the mockups into the published site.
  • Phone and tablet mockups keep design/mockups/shared/mockup.css: they draw the native screens.
  • Icons on the websites and in every mockup come from Lucide, as in the Icons section (ADR 0024).

Icons ​

Every icon is from Lucide, on every platform (ADR 0024). Use its name for the action, never a home-made drawing of one Lucide already has. Icons take their colour from the roles above, and an error keeps its icon. Lucide's drawing stays as it is: a 24 box and a 2 wide round stroke, never filled; only the size changes (24 by default, 20 in chips and small buttons, 16 to 18 beside a line of text).

Accessibility ​

  • Touch targets at least 44 by 44; a visually smaller control, such as the 40 icon button, extends its touch area to 44.
  • Text contrast at least 4.5:1, including small grey labels; 3:1 only for text 24 px and up.
  • Every icon-only button has a label; decorative drawings of Poulpy are hidden from screen readers, and a pose that carries meaning has a description.
  • Nothing depends on colour alone: mood changes also change Poulpy's face and words, errors carry an icon.
