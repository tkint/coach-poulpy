Decisions

0001 · Local-first: the phone is the source of truth

0002 · One Kotlin Multiplatform core for every platform

0003 · Sessions are stored as append-only event logs

0004 · Workout types are modules over one engine

0005 · Ids are UUIDv7 made on the device

0006 · Sync keeps both conflicting edits

0007 · Postgres: columns for structure, JSONB for content

0008 · A curated catalog with stable slugs, updated without an account

0009 · Shared plans are saved synced or as a copy; enrollments pin a version

0010 · Treadmills are read-only metric sources in v1

0011 · A .FIT file export instead of Garmin and Strava APIs

0012 · Design tokens are generated from one file

0013 · Workouts have a format, not a type

0014 · Text lives in one JSON file per language and namespace

0015 · Catalog text lives in translation files

0016 · Mockups are plain HTML in the repo

0017 · Body measurements are stored metric and shown in the person's units

0018 · Live plays a mixed workout with the workout player's steps

0019 · The server runs with Docker Compose on one server

0020 · Every credential resolves to one caller with scopes

0021 · The landing site, the web app and the API each have their own hostname and container

0022 · The server's schema is SQLDelight migrations on Postgres, applied on start

0023 · The websites share one Vue and DaisyUI design system

0024 · Lucide is the icon set everywhere

0025 · The phone forks a conflicting workout, and the server counts changes

On this page

Coach Poulpy ​

A personal training platform where people build workouts, follow plans, train through guided sessions and watch their progress, coached by Poulpy, a reversible plush octopus.

Language ​

Catalog and workouts ​

Exercise: One movement from the curated catalog, identified by a slug that never changes. Avoid: Move, drill

Catalog: The curated, versioned set of exercises shipped with the app and updated without an account. Avoid: Exercise database, library (the library is the user's)

Retired exercise: A catalog exercise no longer offered, kept so the workouts that use it still open. Avoid: Deleted exercise

Variation: A catalog exercise that does the same movement made easier or harder, like the knee push-up and the diamond push-up for the push-up. Variations are equals in one group, ordered from easiest to hardest, and each keeps its own slug, records and history. Avoid: Progression, regression, alternative

Alias: Another name people search an exercise by, like "RDL" or "abdos", kept per language in the catalog and never shown. Avoid: Keyword

Focus: What an exercise is for: strength, cardio, mobility, stretching, warm-up or cool down. An exercise can have several. The exercise list filters by it. Avoid: Category, type (the movement pattern is how it moves, not what it is for)

Position: How the body is placed doing an exercise: standing, seated or on the floor (lying, kneeling, all fours). An exercise can have several. Avoid: Posture, stance

Tag: A fact worth knowing before picking an exercise, worked out from the catalog rather than stored: no jumping, each side, hold, timed. Not an alias, which is only a search name. Avoid: Keyword, label

Format: How a workout is built, chosen when it is created and kept: a circuit goes round several exercises, each done once per round, so its exercises have no sets; sets does one exercise at a time, all its sets with a rest between them, then the next. Avoid: Workout type, kind, sport, category

Workout: A versioned list of parts in one format, ready to be done. Avoid: Routine, program, training

Automatic name: The name a workout gets when it is saved or imported with a blank one: its first exercise, then "(+2)" for the other exercises it uses ("Squat (+2)"), in the app's language. A workout always has a name; once saved the automatic name is an ordinary name and can be renamed.

Part: One section of a workout, holding its steps: the warm-up (at most one, first), a work part (one or more, "Work 1", "Work 2"), or the cool down (at most one, last). Avoid: Phase (a phase is one stretch of a timeline), block, section

Step: One node of a part's tree: an exercise with its prescription, a group, or a rest. An exercise step has a role: exercise or recover; a rest is a recover step with no exercise. Avoid: Item, block

Group: A step holding other steps: a sequence, superset, circuit or interval set with rounds. The builder calls the group it makes a Repeat: steps done a number of times, one level deep. Avoid: Block, round (a round is one pass through a group)

Repeat: The builder's name for a group: "Repeat 4 times" around a run and a walk. It holds exercises and rests, never another repeat. Avoid: Loop, set (a set belongs to one exercise's prescription)

Until button press: A walk or run's duration with no set amount: the step ends when the person taps Next. On the last step it reads until the end, and the tap finishes the session. Avoid: Lap, open-ended

Mixed workout: A workout with at least one walk or run and at least one other exercise, such as a run warm-up then squats. Live offers it after the workouts made only of walks and runs, and plays it with the workout player's steps; only the walk and run steps follow the treadmill (ADR 0018). Avoid: Hybrid

Prescription: What an exercise step asks for: its sets, and per set a target, load, intensity, tempo and the rest before the next set, none after the last. In a circuit an exercise holds one set, and the repeat around it does the rounds. Avoid: Target (a target is one part of a prescription), plan

Plans and scheduling ​

Plan: A versioned set of weeks, each day holding zero or more workouts, written out in full. Avoid: Program, schedule, routine

Enrollment: One person following one version of a plan from a start date. Avoid: Subscription, assignment

Calendar entry: One workout an enrollment schedules on a date, with a status: planned, done, skipped or moved. Avoid: Appointment, slot

Planned workout: A workout a person put on a day themselves, outside any plan. Avoid: Scheduled session

Goal: A measurable target with an optional deadline, whose progress is computed from sessions. Avoid: Objective

Training ​

Session: One workout actually done, from start to end, whether guided, free, recorded from a device only, or a workout with a walk or run followed in Live. Avoid: Execution, activity, workout log, training

In code, the header of a session (its id, source, start and end, workout and notes) is a SessionRecord; Session is the engine's state machine that folds the event log.

Session event: One thing that happened during a session (a phase started, a set logged, a pause, a sample), stored in order and never changed. Avoid: Log entry

Session recap: What opening a finished session shows: its figures, then each part of the workout with the exercises actually done in it (sets, reps or time, load, what was skipped). It is built from the session's events and never edited. In code, SessionRecap. Avoid: Session detail, session summary (that is the figures alone)

Timeline: The flat run of work, rest and transition phases a workout compiles to before a session runs it. A free recording's timeline is open-ended: it grows one manual phase each time the user ends a step, and the pause between two steps is their rest. Avoid: Playlist, sequence

Phase: One stretch of a timeline with its own completion rule: manual, timer, distance or round count. Each phase knows the part it comes from; a part is not a phase. Avoid: Interval (an interval set is a group)

Cue: A prompt the engine raises during a session (countdown, switch sides, next exercise) that each platform turns into sound, vibration or text. Avoid: Notification, alert

Devices ​

Metric source: Anything that streams samples into a session; a treadmill today, a heart rate strap later. Avoid: Sensor, integration

Sample: One timestamped reading from a metric source: speed, incline, distance, heart rate or cadence. Avoid: Data point, packet

Profile ​

Profile: What a person tells the app about themselves, all optional and kept on the phone: a display name, birthdate, pronouns, sex assigned at birth, goal, experience, resting heart rate. Body measurements are logged beside it, not inside it. Avoid: Account (there is none while the app is guest-only), user data

Body measurement: One dated weight or height entry in the person's log. Entries are only added or corrected, never summed, and each chart is drawn from them. Avoid: Weigh-in record, vital

Unit system: Metric or imperial, chosen once in Settings. Everything is stored metric (kg, cm, km) and converted only for display and input, so switching never changes a stored value. Avoid: Locale, measurement preference

Pain window: The time after the person says where it hurts (pain or rehab) during which Poulpy stays on the blue side, in the Patched up pose, and no entry counts as missed. 72 hours by default, or 1 week, 2 weeks, or until the person clears it; setting it again starts the time over. Avoid: Injury mode, sick leave

Body map: A front and a back muscle chart whose areas, left and right apart, light up: where it hurts today when picked, what an exercise works, and, as a heat map, how much a workout works each muscle. Skin has no fill, so it implies no skin tone. Avoid: Anatomy picture, body diagram

Body figure: Which of the two builds the body map is drawn in, Wider shoulders or Wider hips. A drawing choice only: not gender, not linked to sex assigned at birth, never used for estimates. Avoid: Avatar, body type, male or female figure

Pronouns: How the person wants to be addressed, used for French agreement and Poulpy's lines. Never inferred from a name or from sex assigned at birth. Avoid: Gender (the app does not ask for it)

Sharing and coaching ​

Library: A person's own workouts and plans, catalog items they kept, and items shared with them. Avoid: Collection, favourites

Library entry: A shared workout or plan saved in a library, either synced to the author's latest version or as a copy. Avoid: Bookmark, fork

Workout file: A workout saved as a .poulpyworkout file to send to another guest, which opens it in the app to add a copy to their library. Avoid: Backup

Share card: A picture of a finished session (workout name, date, time, sets and any machine values, with Poulpy) sent through the phone's share sheet. It never shows heart rate, and it is a brag card, not a way to share the workout itself (that is the workout file). Avoid: Screenshot, certificate

FIT export: A finished session written as a .fit activity file, saved on the phone from the share sheet of a session (which also offers the session as an image), then uploaded on the websites: Garmin Connect's import page (connect.garmin.com/modern/import-data) and Strava's upload page (strava.com/upload/select). Opening the file in the Garmin Connect app does not import it: the app reads it as a course and asks for a point on a map (ADR 0011). Its FIT sport follows what the session holds: only walks and runs are running (treadmill running when a treadmill sent readings), anything else is strength training for Sets and cardio for Circuit. Strength sets carry their planned reps and weight; a walk or run writes a lap per phase and a record per sample. Avoid: Sync, upload (nothing leaves the phone by itself)

Coach link: The tie an athlete grants a coach, which the athlete can revoke at any time. Avoid: Team, connection

People ​

Guest: A person using the app with no account; everything stays on their phone. Avoid: Anonymous user, offline user

Account: A person's identity on the server, made when a guest signs up; their phones and the website sync through it. Avoid: User, profile (the profile is what the person tells the app about themselves)

Confirmed email: An account's address once its owner has tapped the link sent to it; nothing leaves the phone before (Accounts). Avoid: Verified account, activated account

Sign-in: One phone or browser signed in to an account, named by its device, with its own tokens; revoking a token or reusing a refresh token ends it alone. Avoid: Session (a session is a workout done), login

Outbox: The changes a signed-in phone has made and not yet pushed to the account; signing out waits for it to be empty (Accounts). Avoid: Queue, pending uploads

Cursor: Where a phone's last pull stopped: a number counting every change the server stored for the account, never a time. Avoid: Last sync date, timestamp

Caller: Whoever an API request comes from, as the server sees it: an account, the client it comes through and that client's scopes. Avoid: Principal, user

Scope: One right a token grants, named resource:action (sessions:read). Avoid: Permission, role (a role, like admin, belongs to the account)

Personal access token: A token a person makes in Settings for their own scripts or the MCP server: named, scoped, with an expiry, revocable. Avoid: API key

Poulpy ​

Poulpy: The coach mascot, a reversible plush octopus: blue side when the plan is on track, ember side when a session slipped. Avoid: Avatar, character, octopus

Mood: Poulpy's feeling, one of six shades: proud, happy, recovering on the blue side; annoyed, grumpy, fuming on the ember side. Avoid: State, emotion

Pose: A full drawing of Poulpy for a moment that matters (Champion, Straining, Sleeping...), as opposed to a plain mood portrait. Avoid: Sticker, illustration

Tentacle: One of the eight segments of Poulpy's ring; each finished session lights one, and a lit tentacle never goes dark. Avoid: Point, star, streak

Full octopus: All eight tentacles lit, which shows the Champion pose and starts a new ring. Avoid: Level, badge
